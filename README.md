# Homework 4: OOP in Python

Учебный проект по объектно-ориентированному программированию. Реализована система товаров и категорий с наследованием и
базовым покрытием тестами.

## Структура проекта

- `src/base_entity.py` — абстрактный базовый класс `BaseEntity`. Общая логика для всех сущностей: хранение `name` и
  `description`, обязательный `__str__`.
- `src/base_product.py` — абстрактный базовый класс `BaseProduct` (наследник `BaseEntity`). Общая логика для всех
  товаров: хранение цены, количества, геттер/сеттер цены с валидацией.
- `src/product.py` — класс `Product` (наследник `BaseProduct`). Конкретная реализация товара с логикой добавления в
  общий реестр и обновления существующих позиций.
- `src/smartphone.py`, `src/lawn_grass.py` — дочерние классы с уникальными атрибутами.
- `src/category.py` — класс `Category` (наследник `BaseEntity`). Управление категориями, подсчёт товаров, средний
  ценник.
- `src/order.py` — класс `Order` (наследник `BaseEntity`). Заказ с привязкой товара, количества и расчётом итоговой
  стоимости.
- `src/print_mixin.py` — миксин `PrintMixin` для отладочного вывода информации об объекте при создании.

## Реализованная функциональность

В рамках задания реализованы следующие возможности:

* **Абстрактные базовые классы:** `BaseEntity` и `BaseProduct` с общей логикой (имя, описание, цена, количество) и
  абстрактными методами, которые обязаны реализовать наследники.
* **Иерархия классов:** `Product` наследуется от `BaseProduct`, `Category` и `Order` — от `BaseEntity`. Дочерние
  классы (`Smartphone`, `LawnGrass`) расширяют `Product` уникальными атрибутами.
* **Управление категориями:** класс `Category` для группировки товаров, подсчёта количества, валидации типов при
  добавлении и расчёта среднего ценника с обработкой деления на ноль через `try/except`.
* **Заказы:** класс `Order` привязывает товар и количество, автоматически считает итоговую стоимость.
* **Валидация данных:** проверки на корректность типов (исключение `TypeError` при передаче неверного объекта), контроль
  количества (исключение `ValueError` при `quantity <= 0`) и валидация цены через сеттер.
* **Тестирование:** полный набор тестов на `pytest`, включая проверку уникальной логики наследников, обработку
  исключений и поведение при пустых данных.
* **Работа с данными:** предусмотрена структура для хранения данных (папка `data`) и вспомогательные утилиты (
  `utils.py`).

## Качество кода и инструменты контроля

Код проекта полностью соответствует стандарту **PEP 8**. Для поддержания чистоты и единообразия кодовой базы
используются следующие классические инструменты:

* **Black** — автоматический форматтер кода. Приводит стиль кода к единому виду, устраняя споры о пробелах и переносах
  строк.
* **Flake8** — линтер для поиска стилистических ошибок и нарушений PEP 8, а также простых логических багов (
  неиспользуемые импорты, переменные и т.д.).
* **Mypy** — статический анализатор типов. Проверяет корректность аннотаций типов и помогает избежать ошибок, связанных
  с передачей данных неверного типа.
* **Isort** — утилита для автоматической сортировки и группировки импортов в файлах.

Эти инструменты интегрированы в рабочий процесс и запускаются перед каждым коммитом для гарантии высокого качества кода.

## Стек технологий

- Python 3.12
- Poetry (управление зависимостями)
- pytest + pytest-cov (тестирование и анализ покрытия)
- unittest.mock (мокирование)

## Быстрый старт

**Запуск файла main.py:**
Файл `src/main.py` запускается без ошибок и демонстрирует работу основных классов:

```bash
poetry run python -m src.main
```

**Проверка качества кода (линтинг и форматирование):**

```bash
    # Проверка типов (mypy)
    poetry run mypy src
    
    # Проверка стиля и ошибок (flake8)
    poetry run flake8 src
    
    # Проверка и сортировка импортов (isort)
    poetry run isort src --check
    
    # Проверка форматирования (black)
    poetry run black src --check
```
